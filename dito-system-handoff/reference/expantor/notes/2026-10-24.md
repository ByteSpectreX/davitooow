## Corrections to earlier conclusions

- “Fetch all promos” currently means pages under the returned top-level web categories. It does not cover every app, nested, personalized, guest, or partner catalog.
- Missing Long Expiry in that list does not prove that the account cannot access it elsewhere.
- Recipient support in the official flow does not establish that changing `accNbr` in our own-load purchase request is sufficient. DITO's flow validates the recipient and determines checkout options separately.
- Code inspection found legitimate API references, not a verified backdoor or an eligibility override.
- The Android APK is protected by SecNeo. The exposed static files did not provide the main catalog implementation; the public web/H5 bundles supplied the concrete leads.

## Session state

The dashboard is served on port 5174. Its local sessions live in Node process memory and are lost on restart. Public bundles were inspected without account credentials. No authenticated Long Expiry result was established in this study. This notebook records no real mobile numbers, passwords, OTPs, cookies, or tokens.
